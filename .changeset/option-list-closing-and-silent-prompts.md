Three accessibility fixes, to `OptionList` and to the document surface, each found by a review of a consuming application's slash palette. No export, class or token is renamed or removed, and no prop changes its meaning. One optional prop is added, `closed`, and the markup of `OptionList` changes in one place, said under the first fix.

**Fixed: nothing was announced when the option list closed.** A screen reader was told when the list opened and as its count changed, and was told nothing when it went without a choice: after Escape, after the cursor left the query, after a letter that ended the command. The status region was part of the list and left the page with it, so it could not say so.

- The status region is now the element after the list and not a child of it, and it stays in the page while the list is closed. It is the same element open and closed. When `open` becomes false it is given `closed`, 150 milliseconds later.
- `closed` is a new optional prop. Its default is "List closed.", which is a new text for the owner's approval. It is read on the render that closes the list, so an application can give one closing other words than the next, and an empty string says nothing.
- Two closings are silent. A list whose opening was never announced, because it closed before its count settled, closes unannounced: a writer who types ` /usr/` is not told that a list they never heard of has closed. A list that opens again inside the 150 milliseconds says nothing of having closed.
- **A choice is not told from a dismissal.** Enter is the application's key, and a choice and a dismissal both reach the component as `open` becoming false. So with `closed` left alone, "List closed." follows a choice as it follows Escape. An application that wants silence after a choice, or wants the block named, passes `closed` for that closing. Which of the three a product needs is for a person with a screen reader to hear, and step 12 of the README's script asks it.
- The text stays in the region until the list opens again, as the last label stays in the region of `SyncStatus`. Opening empties it.
- **What changes in the markup.** A closed `OptionList` rendered nothing, and now renders one empty `<span class="ekd-option-list-announce" role="status">`, which is not drawn. An open one has that `span` after `.ekd-option-list` and not inside it. A selector or a test that reads the region as a descendant of `.ekd-option-list`, or that expects a closed list to leave no element, changes. An application that renders `OptionList` only while the list is open takes the region out with the list and hears no closing: keep it in the page and change `open`.
- `check:components` holds that the region is one element through opening and closing, each of the closings above, and that a render of the closed list does not take back a closing that is waiting to be said.

**Fixed: the prompt of an empty block was read as its text.** `.ekd-editor [data-placeholder]::before` draws the prompt with `content: attr(data-placeholder)`, and text a stylesheet generates is part of the element's text for a screen reader. An empty paragraph was read as if the prompt were written in it.

- The rule now declares `content: attr(data-placeholder) / ""` after the plain declaration. The empty alternative text takes the prompt out of what is read (CSS Generated Content Level 3). A browser that does not parse the `/` drops that declaration and keeps the first: the prompt is drawn there, and is read as before.
- In forced colours the prompt is `GrayText`. Every text colour is forced to one ink there, and the prompt was drawn in the ink of the writer's text.
- No token changes. The prompt is `--fg-3`. Measured in the eight palettes it is 5.03:1 at its least on `--bg-canvas`, 5.12:1 on `--bg-surface` and 4.60:1 on `--bg-surface-2`, where WCAG 1.4.3 asks 4.5:1, and `check:contrast` already holds those three pairs. On `--bg-inset` it is 4.36:1 in sepia light and on `--bg-raised` 4.40:1 in sepia dark, which is short. The surface a document is drawn on is the application's choice, so one that draws it on either of those gives the prompt another ink.
- A prompt that is no longer read has to be said somewhere else. The application says it in the description of the text region, or in `aria-placeholder` on it.

**Fixed: the prompt of a table's caption was read as the caption.** An editor puts `data-placeholder="Caption"` on the empty `ekd-table-caption`, and the rule above draws it, so the same fault made a screen reader read an empty caption as "Caption". It is cured by the same declaration, and the caption has no rule of its own to cure.

- An empty caption is now an empty caption to a screen reader: the word "Caption" is not read as its text. A caption that has text is read once, as its text, and has no prompt, since the editor takes the attribute off at the first character.
- A writer who cannot see the page is then not told by the prompt that the empty line under a table is its caption. What tells them is the element: a `figcaption` in a `figure`, where a screen reader says so. Whether each does has not been heard.
- `check:components` holds the two declarations and their order, that one rule alone draws a prompt from `data-placeholder`, that the caption draws none of its own, and the colour in forced colours, in `styles/editor.css` and in the two entries that carry it.

Not tested: no screen reader was run, for any of the three. That a polite region kept in the page speaks a text written to it, and that an empty alternative text takes generated content out of what is read, are read from the specifications and not heard. Chromium 152 was given the built stylesheet: it parses the second declaration, computes `"Caption" / ""` for an empty caption and no generated content for a filled one, and draws the prompt in `--fg-3`. What it then hands a screen reader was not read. Which other browsers parse the `/`, and from which version, was not checked. Forced colours were not turned on. Firefox and Safari were not run. jsdom has no generated content and no accessibility tree, so the checks hold the markup, the timing, and the declarations by name.
