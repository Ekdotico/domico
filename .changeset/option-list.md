`OptionList`, a list of options at the text cursor that is filtered by what is typed and never takes focus. The Ekdotico application opens one when a writer types `/` (FR-ED-10 to FR-ED-12) and may draw no control itself (FR-AU-88), and until now the package had no drawn listbox. `@ekdotico/domico/components` now exports `OptionList` and four functions, `optionListKey`, `optionListAttributes`, `optionListOptionId` and `placeOptionList`, with the types `OptionListProps`, `OptionListItem`, `OptionListAnchor`, `OptionListDismissReason`, `OptionListKeyEvent`, `OptionListKeyResult`, `OptionListTextAttributes` and `OptionListPlacement`. One stylesheet entry is new, `styles/option-list.css`, which is also in `styles.css` and `styles/components.css`. No export, class or token is renamed or removed, **no token is added**, and the package still has no runtime dependency.

The list never has focus, so the control is in two parts.

- `OptionList` is `role="listbox"`, named by `label`, with `role="option"` children. It is fully controlled: the application holds `open`, `options` and `activeId` and does the filtering. Each option is `{ id, label, detail }`, with `detail` an optional second text at the end of the row. The active option is `aria-selected="true"` and the others `"false"`. An option's element id is `optionListOptionId(id, option.id)`, which is `id`, `-option-` and the option's id, the same on every render. With no options the listbox is not rendered and `empty` is shown in its place. Closed, it renders nothing.
- A press on an option calls `onSelect` and does not move focus: the default of `pointerdown` and of `mousedown` is prevented over the whole list, and the option is chosen on the click. The pointer moving onto an option calls `onActiveChange`. A press outside calls `onDismiss('press-outside')`. The control handles no key.
- `optionListKey(event, { options, activeId, maxVisible })` reads a `keydown` in the text and returns `{ activeId }`, `{ select }`, `{ dismiss: true }` or `null`. Down and Up move by one and stop at the ends without wrapping, as the WAI-ARIA Authoring Practices describe for a listbox popup. Home and End go to the ends, Page Down and Page Up move by `maxVisible`, Enter chooses the active option, and Escape dismisses. Every other key is `null`, and so is every key while an input method is composing, with a modifier held, or, Escape apart, with no options. It does not prevent the default; the application does when the result is not `null`.
- `optionListAttributes(id, { open, options, activeId })` returns what the focused text region carries. While the list shows at least one option: `aria-autocomplete="list"`, `aria-haspopup="listbox"`, `aria-controls` and, with an active option, `aria-activedescendant`. Otherwise all four are `undefined`, which removes them. The region keeps `role="textbox"`. It is not given `role="combobox"`, and it is not given `aria-expanded`, which WAI-ARIA 1.2 does not support on a textbox.
- A polite status region inside the control is given `status`, or `empty` when there are no options, once the text has stood for `announceAfterMs`, 500 by default. A count passed through while typing is not announced, and neither is one that did not change. Both texts are the application's.
- `anchor` is the cursor, as a rectangle in viewport coordinates or a function that returns one. The list opens under it, above it where it does not fit below, and on the side with more room, held to that room, where it fits on neither. It is kept 16 pixels from each edge of the viewport, and is placed again on a scroll and on a resize, which is why a function is the form to pass. `placeOptionList` is that arithmetic as a pure function.
- The list is `position: fixed`, and is shown as a manual popover, in the top layer, where the browser has the Popover API. Its position is written to the element's `style` by script, and its row limit is a `style` attribute; no stylesheet is injected. In a browser without the Popover API an ancestor with a transform still positions and clips it.
- It shows `maxVisible` rows, 8 by default, and scrolls, keeping the active option in view. It is 20rem wide, or the viewport less 16 pixels each side where that is less. A label that does not fit wraps. A row is `--sp-7` high at its least.
- The active option is drawn with a boundary in `--accent` and the ground `--accent-soft` together, on `--bg-raised`, and with the system colours `Highlight` and `HighlightText` in forced colours. The list has no transition and no animation.

It uses existing tokens alone: `--bg-raised`, `--rule`, `--radius-md`, `--radius-sm`, `--shadow-2`, `--accent`, `--accent-soft`, `--fg-1`, `--fg-2`, `--font-sans`, `--font-mono`, `--fs-sm`, `--fs-xs`, and the spacing steps.

`check:contrast` gains two pairs: `--fg-2` on `--accent-soft` at 4.5:1, for the detail on the active row, where the lowest is 6.40:1 in sepia light, and `--accent` on `--accent-soft` at 3:1, for the boundary of the active row against its own ground, where the lowest is 4.57:1 in parchment dark. `check:components` gains six cases.

`keepInViewport`'s margin, `EDGE_MARGIN_PX`, is now exported from the internal `viewport.ts` so the placement shares it. It is not part of the public barrel.

For a consumer: `ekdotico-check discipline` derives its list from the barrel, so from this version a local `OptionList`, `optionListKey`, `optionListAttributes`, `optionListOptionId` or `placeOptionList` is reported as a reimplementation.

Not tested, and to be done before the application ships the palette: the list has not been heard in VoiceOver, NVDA or JAWS, and support for `aria-activedescendant` on an editable region differs between them. Where one does not follow it, a writer hears the count and not each option, and the application can add the active option's label to `status`.
