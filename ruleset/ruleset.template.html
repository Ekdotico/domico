Two things follow, and they set the shape of every rule below.

The token layer is already solved. All three apps define effectively zero colour, type, spacing, radius, shadow, or motion tokens of their own — docs declares one per-app geometry value, --chat-panel-w, and re-declares --table-sticky-offset on body rather than :root to win a cascade tie it verified by reading link order out of a production build. Drift now arrives as a fork of one projection, or as documentation nobody updated. Not as a rogue hex value. The rules below are aimed at those two failure modes, because those are the two that are actually happening.

2 · Tokens

Four themes, two modes, eight palettes. 43 colour tokens resolve under every one of them, plus 71 theme-invariant scale tokens. Values live in exactly one place: domico/tokens/generated/tokens.css, generated from tokens/source/*.json.

The eight palettes --bg-canvas, light and dark

Each pair above is what the theme switcher samples: the light and dark --bg-canvas of each theme. Note mono light is oklch(100% 0 0) — deliberately pure white, the one place the system uses it, because a monochrome high-focus reading theme wants no cast at all.

Rule 01

A new design need is a new token, never a literal

Colour, type, spacing, radius, shadow, and motion come from custom properties. A token added to an app stylesheet forks the design system; a token added to tokens/source resolves in all eight palettes at once.

Do
border-radius: var(--radius-lg);
color: var(--accent);
font-size: var(--fs-base);
Don't
border-radius: 10px;
color: #5a4a7a;
font-size: 15px;

A literal font-size in px is a defect on its own terms: the scale is rem so a reader who raised their browser font size scales the whole interface with it.

Rule 02

Never write a fallback value into var()

A fallback that restates a token is a second source of truth with nothing keeping it honest. deree has 44 of them and seven have already gone stale — silently, because a fallback only shows itself when the token is missing.

deree/app/globals.css:200, 209, 245, 258, 259, 265, 384. docs has one fallback in 4,144 lines, and it falls back to another token.

One precision, because the brief reads more strictly than it means. It says to reference the token “with no fallback list” — but the token definitions themselves carry full font stacks, and that is correct: the stack belongs in the token, where it is authored once, and consumers reference only the token. The prohibition is on a consumer restating a value var() already knows. Thirteen of deree's fallbacks restate the family name, which is the banned form exactly.

And note precisely why this is dangerous, because the obvious reading is wrong. Those seven stale fallbacks were never rendering. var() reaches its fallback only when the custom property is unset, and the token layer sets all of them — verified by computing the values in a running build, where var(--sp-12, 4rem) resolved to 128px, not 64px. Stripping them moved nothing on screen.

That makes the defect worse, not milder. Seven false statements about the design system sat in the stylesheet where no pixel was able to contradict them, waiting to become true the day a token was renamed. A wrong value that renders gets found. A wrong value that cannot render does not.

Rule 03

Auto is the absence of data-mode, not a value of it

This is the mechanism, not a convention. :not([data-mode]) is what arms the prefers-color-scheme block, and what stops a dark operating system from overriding an explicit Light choice. Writing data-mode="auto" breaks both directions at once.

<html data-theme="parchment">                    ← auto: defers to the OS
<html data-theme="parchment" data-mode="light">  ← explicit: beats the OS
<html data-theme="parchment" data-mode="auto">   ← wrong. never emit this

The explicit-dark and automatic-dark blocks are hand-maintained twins — CSS cannot alias an attribute selector to a media query. They are verified identical across 43 declarations × 4 themes. Change one, change the other.

Rule 04

Greek glyphs never come from --font-serif

Crimson Pro ships no Greek subset. The docs build emits six Crimson Pro faces — normal and italic across latin, latin-ext, and vietnamese — and not one covers U+0370–03FF. Commissioner and Fira Code both got a Greek face in the same build from the same tool, so this is a limitation of the face, not a subsetting choice.

The consequence is live on the reference app's own title page. docs/app/page.tsx:49 renders εκδοτικό, and docs/app/globals.css:1637 sets it in var(--font-serif). It therefore falls through to Iowan Old Style on macOS and Times New Roman elsewhere: the one word carrying the brand's name is the one word not in the brand's typeface, and it looks different per operating system.

Do
.title-page-greek {
  font-family: var(--font-sans);
}

Commissioner has Greek coverage. A stated exception to the role rule, for glyphs the serif cannot set.

Don't
.title-page-greek {
  font-family: var(--font-serif);
}

Silent fallback. No error, no warning — just a different typeface per OS.

The Greek wordmark has the same fault one layer deeper: domico/assets/logo/logo-wordmark-greek.svg:10–11 uses live <text> with no font-family, its <defs> block is empty, and the .latin and .greek classes it references are defined nowhere. Outline both nodes to paths: a mark whose letterforms depend on a webfont resolving is not a mark.

Rule 05

Load the italic subset, or lose it silently

praktico/src/app/layout.tsx:39–43 omits style: ["normal", "italic"], which docs/app/layout.tsx:40 has. The package sets font-style: italic on the selected theme's name and on .lede, so those render as browser-synthesised oblique — visibly worse, and exactly the failure where an individually tuned set stops reading as a set. Take fontConfig from @ekdotico/domico/fonts, which already declares it; all three apps currently restate the config by hand instead.

Rule 06

One trigger, top right, disclosing the full optionset

The control in this page's corner is the proposal. Open it, change the theme, and the page you are reading retints — which is the point: the swatches exist to be compared against real content, so the surface must stay visible while choosing.

That requirement decides the ARIA pattern. It is a disclosure plus a non-modal popover wrapping the two existing radiogroups — not a menu, because a menu closes on activation and would force a re-open per comparison; and not a dialog, because focus-trapping a preference with no confirm step hides the page the swatches are meant to preview. The disclosure adds aria-expanded and aria-controls to one new button and changes nothing inside either radiogroup.

KeyBehaviour
Enter / SpaceToggle the popover; aria-expanded reflects state
on openFocus the checked theme, not the first
EscapeClose, return focus to the trigger
TabTwo stops inside, then leaves. Non-modal, no focus trap
← → ↑ ↓Move and select within a group; both axes, because a reader cannot see which one the author had in mind
Home / EndEnds of the group

Ships once, in the package, as domico/src/theme/AppearanceMenu.tsx. Each app then deletes its own composition: three lines in praktico, seven each in docs and deree. Do not ship it in two places on one page — two instances means two elements claiming aria-label="Colour theme".

Because it is a disclosure and not a dialogue, it takes no aria-modal and no focus trap. The inverse rule holds for anything that does claim aria-modal="true": it owes a Tab cycle and an inert background, both of them, every time. docs gets this right in two of three overlays — the command palette and the chat panel share a refcounted inert helper and trap Tab explicitly, while the mobile drawer declares aria-modal="true" and does neither, so a keyboard reader tabs silently out of the open drawer into the page behind it. Claiming the role without keeping its promise is worse than not claiming it.

Rule 07

Swatches carry both candidates; CSS picks

Only one [data-theme] is live at a time, so an inactive theme's canvas cannot be read from computed CSS — and asking a hook would ask what no server can answer, because Auto defers to a preference that never leaves the reader's machine. So each swatch is handed both values and the stylesheet resolves at paint. The specimen in section 2 uses exactly this mechanism.

<span class="theme-swatch" aria-hidden="true"
      style="--swatch-light: …; --swatch-dark: …" />

aria-hidden is correct here, not an oversight: the swatch is decorative and the button takes its accessible name from the sibling label, so colour is never the sole carrier of the choice.

5 · Components

Ten components ship in the package. docs uses all ten, deree two, praktico two — and praktico's figure is not a preference. Eight of them hardcode unprefixed global class names that a CSS Module cannot own, and praktico forbids importing a global component layer.

A component used twice comes from the package

The unblocking move is not a new mechanism. It is the factoring the package has already done twice for exactly this reason — reset.css split out at 0.7.0, appearance.css at 0.8.0. Continue it: ship one stylesheet per component, so an app imports only the CSS for what it renders.

Rule 09

Never fork a projection of the palette

The last surviving fork in the estate is not a rogue colour in a component. It is a second copy of the whole palette, projected into another format, in the reference app. docs/components/docs/Mermaid.tsx:45–278 carries 216 hex literals across eight palettes and never imports @ekdotico/domico/mermaid, which the token pipeline generates for exactly this purpose.

Diffed value by value: 202 identical, 14 drifted. That ratio is the proof — it is a copy that has since diverged, not an independent design.

The other seven drifted values are tertiaryColor. All 216 pairs were compared.

This one needs a decision, not a revert — and it is the only rule on this page where the reference app may be right and the package wrong. On lineColor, docs gives each theme its own accent while the package flattens all four to gilt. Diagram edges that pick up the theme's own colour are arguably the better design, and nothing in the house style forbids it.

But docs is also running a stale value: #8b6f3a is the pre-correction gilt, and #6f5826 is the darkened one adopted after the original failed AA as small text. On a parchment canvas that is 4.43:1 against 6.33:1. Since lineColor paints edge strokes, the 3:1 non-text threshold applies and both pass — so this is an integrity defect, not an accessibility one. Do not report it as an AA failure.

So: decide whether per-theme diagram edges are canonical. If they are, add them to tokens/source/ and regenerate, so the better design becomes the generated one. Either way the local map is deleted and the import taken. The generated file is trustworthy: its build fails if any colour drifts more than 0.6 in lightness or chroma through the oklch → hex → oklch round trip.

Resolved. Per-theme edges were adopted as canonical and promoted into the token source as --diagram-edge, which is also now measured by the contrast guard at the 3:1 non-text threshold. That promotion reconciled seven of the eight lineColor values above, leaving parchment-light — where the corrected gilt stands and the fork's pre-remediation value goes — plus tertiaryColor in seven palettes: eight residual values, not fourteen. The table above is the pre-promotion snapshot, and the difference between the two counts is the promotion itself.

The swap was then verified against painted pixels, not serialised markup, which turned out to matter: the emitted SVG retains presentation attributes the stylesheet overrides, so grepping the markup finds actor fills, note fills and lifeline strokes that never render. Reading fill, stroke and color back from the DOM gave 168 assertions across eight palettes and five diagram types, zero failures, and confirmed that of Mermaid's 251 resolved slots the only six our 27 never touch belong to architecture and gantt diagrams, which this estate does not draw.

6 · Motion

Rule 10

Fades, at --dur-base with --ease-soft

Transform is permitted only where a surface enters or leaves the viewport — a drawer sliding, a popover rising. It is prohibited on anything already on screen: hover, focus, and state changes fade, they do not move. The popover in this page's corner uses translateY(-4px) because it enters; nothing else on the page moves at all.

No bounce, no spring, no elastic. Press should feel like paper pressing on a soft surface, not a button bouncing. Timing lives in --dur-fast (140ms), --dur-base (220ms), and --dur-slow — never as a literal. The package itself breaks this at appearance.css:116–119, where three raw 140ms cubic-bezier(0.22, 1, 0.36, 1) values numerically equal the tokens today and will fork the moment either moves.

Rule 11

Reduced motion is a flat prohibition, and nothing may wait on transitionend

The written rule is wrong here and the code is right. Both .impeccable.md files state that reduced motion shortens durations to 0.01ms rather than setting transition: none, and call the distinction load-bearing. The package ships the opposite — a universal animation: none !important; transition: none !important — and it is correct: a duration ceiling sets how long a transition takes but does not stop an already running animation, so a blinking caret freezes at whatever opacity the frame caught it. That bug is why the ceiling was abandoned.

The stated rationale for the ceiling was that components wait on transitionend. That was checked: zero transitionend or animationend listeners exist across all four repositories. Nothing depends on it, so nothing breaks.

Two consequences. Amend both briefs to the flat prohibition, and delete the surviving 0.01ms blocks — there were eight of them in the reference app, and they were dead code, not a competing philosophy. They override transition-duration only, while the package's shorthand also sets transition-property: none, which nothing overrode; so nothing transitioned regardless of the duration they specified. Same conclusion, and worth stating precisely, because "two rules fighting" and "one rule that never applied" call for different fixes.

And never gate an unmount on transitionend: under a flat prohibition the event never fires, so a component that waits for it hangs permanently, for exactly the readers least able to work around it. Keep the surface mounted and toggle a class instead.

Rule 11a

Never transition visibility with a duration

This one was found by shipping it. The appearance control is specified to focus the reader's current theme when it opens; the effect and the selector were both correct, and it did not work — focus stayed on the trigger.

visibility is a discrete property. Under a transition it does not interpolate: it flips when the easing output passes 0.5, which with --ease-soft is roughly 15ms into a 220ms transition. That is inside the first frame, so the effect ran while the panel still computed visibility: hidden — and focus() on a hidden element is silently ignored. No error, no warning, and nothing in the source that reads as wrong.

Do
/* closed */
transition: opacity var(--dur-base) var(--ease-soft),
            visibility 0s linear var(--dur-base);
/* open */
transition: opacity var(--dur-base) var(--ease-soft),
            visibility 0s linear 0s;
Don't
transition: opacity var(--dur-base) var(--ease-soft),
            visibility var(--dur-base) var(--ease-soft);

Focusable only after the flip. Also cuts the closing fade off halfway.

Zero duration, delayed to the end of the fade. Instant on opening, so the surface is focusable in the same frame; held visible through the close, so the fade is not truncated. The guard now asserts it, and the assertion was mutation-tested by reintroducing the duration and confirming it fails.

7 · Prohibitions

These are the ones with teeth, because each has been violated at least once.

Rule 12

No coloured edge stripe, by any mechanism

The house style prohibits coloured left-border accent cards by name. It is violated in two places, by two different mechanisms, and one of them is the component library itself.

In the package: components.css:378–385 draws a 3px tinted ::before stripe on every non-note Callout. A pseudo-element evades the letter of a ban written about border-left while being precisely what the ban exists to prevent. Both docs and deree render it.

In docs: four uses of border-inline-start: 2px, of which one is a true violation — globals.css:563 puts a 2px gilt stripe on a blockquote that already has a surface, a hairline border, and a radius. That is a card with a coloured edge, exactly the named pattern. The other three are bare blockquote rules with no card surface, plus a transient :target locator; those are typographic convention rather than decoration.

The rule is the pattern, not the property. Re-treat Callout with a full hairline and a background tint — it already carries a title and role="note" to signal tone. Drop globals.css:563 to a hairline and carry the gilt as a --hl-quote wash, or remove the card surface and keep the rule. Then rule explicitly on the bare 2px blockquote: if it is house style, write it into the brief and name the ceiling. An unwritten exception is how a ban erodes.

Rule 14

Documentation that contradicts the code is a defect with a severity

Every app migrated onto the package. Not one updated its written account of it. This is the drift that matters most, because the enforcement hooks feed these files to agents on every edit — so the most likely “corrective” action is to undo the correct architecture.

  • praktico/CLAUDE.md and its token catalogue point Rule 1 at src/styles/tokens.css, deleted in commit 0a76b63. The PreToolUse hook injects that dead path on every CSS or TSX edit.
  • Both cite src/lib/appearance.test.ts as guarding the dark twins. The file does not exist, so the documented guard is absent.
  • --measure is documented as 68ch and is 72ch. Three tokens listed “deliberately absent” are defined and in use.
  • deree/app/layout.tsx states there is no switcher on the site. SiteFooter.tsx:31 has rendered one since it landed.
  • deree/.impeccable.md is a verbatim copy of the docs brief — still titled “Ekdotico Docs”, still naming the superseded Source Serif 4 / Inter Tight / JetBrains Mono trio.
  • praktico's specification forbids the shared package its own package.json depends on.

Rule 15

A version you cannot read is a version you cannot adopt

domico/package.json declares 0.10.0. Its CHANGELOG.md stops at 0.4.1 and its git tags stop at v0.2.0 — six published versions with no changelog and no tag. A consumer cannot tell what a bump contains, which is the whole argument against taking one.

Pin exactly, as praktico does. docs and deree both carry ^0.10.0; all three resolve to 0.10.0 today, so the caret is a latent fork that arms itself the day 0.11.0 publishes.
